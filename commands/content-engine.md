## DEEP STORYBOARD STANDARD (MANDATORY, before any render): [[reference-deep-storyboard-standard]]
For ANY video this skill produces, the storyboard King approves must hit MiniMax depth, modeled on
the **MiniMax Hub flow** by @theanimationstudio (King's reference, the "deep storyboard to the
maximum" he loved). The principle in his words: "marked out to the depth... done to the maximum
possible best ability. That should be the whole point." It **SUPERSEDES** any lighter "shot list"
step in Layer 3 above. No surface-level boards. It enforces **Rule #17** (consensus, model the
proven winner) and **Rule #18** (the board must be VISUAL, real frames, not just text).

**The deep storyboard = THREE deliverables, IN THIS ORDER:**

1. **Comprehensive Design Sheet Brief**: the full written spec up front. Project title · logline /
   goal · duration · aspect ratio (Panel Ratio, 9:16 for short-form) · Visual Style (art direction +
   the EXACT palette) · Plot Scope · the character · the caption style · the music · the pacing · the
   scene map.
2. **Character Model Sheet**: the hero character rendered from MANY angles, poses and expressions (a
   turnaround sheet) so it stays identical in every shot. This is the consistency lock.
3. **Shot-by-shot production storyboard**: EVERY scene shown as a real still frame (exactly how the
   final frame looks: background visual + character + caption + headline), each mapped to its exact
   script line, annotated with these per-scene fields **IN THIS ORDER (emotion first, per King):**
   - **Scene number + time range**
   - **VO**: the exact script words for that beat
   - **Caption on screen**: the active / highlighted word called out
   - **EMOTION**: start here, always
   - **Shot type**
   - **Camera / Motion**: HOW the still becomes a moving shot (the exact animation, e.g. slow
     push-in 1.0 to 1.06 Ken-Burns · parallax drift · glitch cut · shake on beat)
   - **Visual source + Tool**: AI image via kie.ai Nano Banana / Pexels b-roll / in-engine graphic,
     PLUS the motion engine (HyperFrames GSAP or Remotion)
   - **SFX / music cue**
   - **Transition out**
   - **The exact image / motion PROMPT used** (Rule #18 requires the real prompt)

**⚠️ RENDER REAL FRAMES, NOT MOCKUPS (the depth lesson, King 2026-06-28).** Each shot frame on the board
must be an **actual rendered image at production quality** (the MiniMax reference's frames are real
cinematic renders, that IS the depth), **not a crude HTML/CSS mockup with a flat character pasted on a
gradient.** A mockup-quality board signals a mockup-quality video and King will (correctly) reject it.
For a character-led brand: **image-to-image off the LOCKED character** (`gen_router.py image` → kie
nano-banana, ~$0.08/frame, ~$1 for a 12-shot board) to get cinematic, varied poses while keeping
identity EXACT, then composite captions/phone/cards/annotations over the render. **Free/cheap image
tools (Pollinations Flux, etc.) CANNOT hold a specific character's identity** (they invent a new face), use them only for backgrounds/b-roll, never the character ([[reference-image-gen-cost-identity]]). Vary
poses across shots (calm hero vs dynamic) so it reads like a real video, not the same frame 12 times.
This is the paid step that's worth it: it shows King the true quality BEFORE the full build.

**The agent flow that builds it (MiniMax Hub):** Reference image -> Visual Style -> Panel Ratio
(9:16 for short-form) -> Plot Scope (Plot + storyboard sheet) -> generate. **Nothing renders until
King approves this visual board start to finish** (the APPROVAL GATE above still applies).
Deep-dive + how every project adopts it: [[reference-deep-storyboard-standard]].

## REFERENCE-QA (MANDATORY): match the data, not just "does it render"
King's standing rule, in his words: "you need to QA against the results/inspiration we are using to
make sure we match our competitors and data... the similarities are in check for best quality results.
not just for voicing, for the majority of QAs we do, because we get our inspo from data and work from
there." Because we model the proven winner (Rule #16 + #17), **QA is NOT an internal check** ("does it
render, no errors, no overflow"). When a reference / competitor / data source exists (which is the
DEFAULT here, since every layer above is built off harvested winners), **QA is a MEASURED SIMILARITY
CHECK against the actual reference**: pull the reference's real numbers and compare ours dimension by
dimension, then FIX until ours matches. **This SUPERSEDES internal-only QA whenever a reference exists.**
Internal-only QA is the exact failure mode that let a slideshow-quality video ship when the real
references are far tighter. Deep-dive: [[reference-reference-qa-standard]].

**The method (5 steps):**
1. **Pull the real reference(s)** we are modeling. Download the competitor video/asset, never guess.
   Free: **yt-dlp** to download · **ffmpeg** scene-detect for cut-counting (`select='gt(scene,0.3)'`) ·
   **faster-whisper** for voice words-per-second + whether a voiceover even exists · frame extraction +
   reading the frames for visual/caption style. No paid API needed.
2. **Measure the reference** on the dimensions that matter for the medium. For **SHORT-FORM VIDEO**, at
   least: **voice words-per-second** + **is there a voiceover at all** · **cut length (seconds per cut)** ·
   **caption style** (font, color, word-grouping, position) · **visual format** (real footage vs
   screen-recording vs AI clips vs stills) · **energy / pacing** · **hook in the first 2-3 seconds**.
3. **Measure OURS** on the SAME dimensions.
4. **Build a side-by-side scorecard** (reference target vs ours vs pass/fail) and **FIX every miss**
   until ours is "not unlike theirs."
5. **Only then is QA passed.** Never report QA as passed on internal checks alone when a reference exists.

**VOICE specifically:** the voiceover must be **EDITED to fit the video** (tightened to the reference
words-per-second, dead gaps cut, aligned to the cuts/beats), **not left as raw TTS or a raw take.**
"Edited to perfect for the video" is the bar (this is on top of the audio-mastering chain in Layer 4).
This applies to the **majority of QAs**, not just voicing. Voice is just one dimension on the scorecard.
