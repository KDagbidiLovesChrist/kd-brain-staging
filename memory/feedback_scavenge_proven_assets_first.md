# Scavenge proven assets FIRST · prompts, code, repos, storyboards

**King's instruction (2026-07-14, voice, from his phone):** "There's no originality to it... find good prompts, codes, git repos to use and work from there... the planning and storyboard/visual board will be so detailed. I have people on Instagram's storyboards who we can model off... essentially using your smart Fable 5 skills to max you out the best we can."

## The rule
When executing ANY idea, the first move is a **scavenge pass**, not a blank page:

1. **Prompts** · reuse the vetted prompt/SOP already in the brain; if none fits, hunt the proven best prompt for that domain before writing one (Rule #25's "best PROMPT").
2. **Code** · search GitHub for existing repos/libraries that already solve the problem (or 80% of it). Fork/adapt/learn from them instead of hand-rolling. Free-first (Rule #12/#16).
3. **Skills** · `/find-skills` scouts the proven best way (Rule #17's reflex).
4. **Storyboards / visual boards** · model the detail level off the storyboard creators King follows on Instagram. Boards stay VISUAL (Rule #18): a frame mockup + exact prompt per shot, start to end, at reference-creator detail.
5. **Fable 5 maxed** · lean on the model's full planning/reasoning depth on every non-trivial build; the scavenge pass + deep visual planning IS how we max it.

## The boundary (no contradiction · Rule #19)
This extends, not replaces, [[feedback-build-originals-not-clones]]: we model **techniques, patterns, structure, and quality**, we respect licences on code, and we never ship a 1:1 clone of someone's site/design with a brand swap. Repos: check the licence (MIT/Apache = fair game; no-licence = learn from, don't copy).

Scratch-building burns hours and credits; proven assets are pre-validated by the market (wisdom-of-crowds, Rule #17). Faster ship = faster first euro.
