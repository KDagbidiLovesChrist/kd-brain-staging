King watched many MARKER iterations (full-screen site footage + bold caption + dark cards, even with multi-shot zooms + deep dives) and said: **"it looks exactly the same, doesn't look edited, not like the YouTube videos."** He was right.

**Why:** A premium "scroll one site for 12s + caption" is a fundamentally different thing from an *edited* video. The reference edits (Nate Curtiss) cut **every ~0.5-1 second**, every cut a **different visual** (character/b-roll/screen-grab/3D prop), with **big pop-text changing on almost every cut** + **motion graphics** (number counters, graphs, icons). Zooming on one scrolling clip can never become that.

**Why:** It also explains why the multi-agent team kept producing the same look, **they used the same engine**. More agent passes on the wrong foundation = the same result. The fix was a NEW engine (`KineticEdit`, fast-cut montage), not a reskin.

**How to apply:**
- When King (or a client) wants a video "like [fast viral edit]", measure the gap concretely: re-watch the reference at ~0.5s intervals and count the cut rate + visual variety. If mine holds >2-3s per shot with one static caption, it is NOT that style.
- Build for the grammar: a cut every ~0.8s, a different visual each cut (intercut footage flashes + text punches + stat counters + icon rows), pop-text + a sound on every cut.
- **Script-first**, then edit the visuals TO the script's beats (the talking drives the cuts).
- **Prove the STYLE on a short ~12s proto first**, side-by-side vs a real reference frame, before rendering anything full-length.
- Be honest early when the approach (not the effort) is the problem. Links: [[project-muba-promo-video]], [[feedback-reference-driven-design]].
