# Audit Before Build, Inside the Brain Itself

**What happened (2026-08-07):** mid-way through designing a new `_ops\CAPABILITY_REGISTRY.md` to map every
agent/skill King has, discovered he already had three systems doing that job: `commands\subagent_registry.md`
(the Standing Army), `_ops\SKILL_TIER_LEDGER.md` (trust-earned tiers), and the Brain DCIM's Agent HQ
(auto-regenerating every 15 minutes). Building the new file would have been a weaker, hand-maintained
duplicate of something already live. Caught before writing it, extended the existing systems instead
(added a LIVE/PARTIAL/BROKEN/DORMANT status field to the Standing Army table, wired the DCIM generator to
read and render it).

**It happened again minutes later, same session:** about to add GREEN/YELLOW/AMBER/RED accountability tags
to `memory\ACTIVE_PROJECTS.md` (an 80-line dense project-history file with its own existing NEW/UPDATED/
COMPLETE/PENDING badge system), when the actual right home was `CLAUDE.md`'s own short one-line-per-project
dashboard, the section built for exactly this kind of at-a-glance status.

**Why this is worth its own entry, not just folded into Rule 25:** both misses happened *after* already
knowing the general principle ("check the 111 skills first," "best tool not nearest to hand"). Knowing the
rule didn't prevent the near-miss, actually reading the target file's real structure before proposing
something new did. The habit is specifically: read what's there before deciding it's missing.

## How to apply
Before creating any new file, table, or column anywhere in this brain: grep/read the folder it would live
in and the files that already claim to do something similar, not just recall from memory whether something
"probably" exists. This is now written into `_ops\CREED.md` §2 (Logic organises itself) and `CLAUDE.md`
Rule 15, so every session inherits it structurally, not just as a memory to recall.
